# 26.46.0 마스터 사용자 시나리오

마스터 사용자 시나리오는 앱 정본에서 확인한 주요 기능을 실행할 수 있도록 구성합니다. 이번 버전의 변경 티켓과 기존 기능을 함께 확인합니다. 검색도 통합 검색·필터·정렬에 더해 검색 홈 탐색, 크리에이터 검색, 해시태그 검색까지 포함합니다.

각 기능은 사용자가 진입해 주요 행동을 마치고 결과를 확인하는 흐름으로 작성합니다. 역할·공개 범위·참여 상태에 따라 결과가 달라지는 경우도 포함합니다. 화면이 열리는지만 보지 않고, 등록·조회·수정·삭제나 지원·수락처럼 해당 기능의 주요 행동을 수행하는지 확인합니다.

주요 기능은 39개 시나리오·175단계로 확인합니다.

## 사용자 유형별 실행 경로

신규 사용자의 첫 가입과 기존 사용자의 업데이트를 각각 확인합니다. 가입 이후의 공통 기능은 두 계정이 역할을 나누어 함께 테스트합니다.

신규 사용자는 26.46.0을 처음 설치하고 가입해 프로필을 등록합니다. 작업물·클럽·대화 이력이 없는 상태에서 첫 작업을 올리고, 대화를 시작하고, 클럽에 참여할 수 있는지 확인합니다. 기존 사용자는 이전 버전에서 활동한 계정으로 업데이트합니다. 업데이트 전의 정보·참여 관계·설정이 유지되고, 기존 기록을 개편된 화면에서 계속 이용할 수 있는지 확인합니다.

공통 기능은 작성자와 조회자, 모집자와 지원자처럼 서로 다른 역할을 맡아 한 흐름으로 진행합니다. 프로젝트는 기존 사용자가 만들고 신규 사용자가 지원합니다. 팀은 신규 사용자가 만들고 기존 사용자가 지원해 역할을 바꿉니다. 글·일정·자료·노트도 한쪽이 등록하면 다른 쪽이 열거나 참여하며 양쪽의 결과를 확인합니다.

앞에서 만든 콘텐츠와 받은 알림은 다음 시나리오에서 이어서 사용합니다. 같은 조작을 반복하는 대신, 신규 계정의 첫 사용과 기존 계정의 기록 유지처럼 결과가 달라지는 부분을 각각 확인합니다. 수락·거절·초대 등 서로 다른 대상이 필요한 단계에는 보조 계정을 사용합니다.

실행 기록에는 사용자 유형과 실제 역할, 각 계정에서 확인한 결과를 구분해 남깁니다. 공통 흐름을 함께 완료했더라도 신규 사용자의 첫 행동이나 기존 기록의 유지를 확인하지 못했다면 그 항목은 별도로 남깁니다. 아래 실행 순서에 따라 이 방식으로 진행하고, iOS와 Android 결과를 각각 기록합니다.

| 사용자 | 시작 조건 | 먼저 확인할 것 | 실행 순서 |
|---|---|---|---|
| 기존 사용자 E | 이전 버전에서 활동한 계정으로 앱을 업데이트합니다. 프로필·작업물·클럽·채팅·알림 설정이 있습니다. | 로그인·기존 정보·관계·알림 설정이 유지되고 기존 프로젝트·팀이 개편된 화면으로 열리는지 확인합니다. | 01 → 아래 공통 실행 순서 → 25~26의 정리 |
| 신규 사용자 N | 26.46.0을 처음 설치하고 새 계정으로 가입합니다. 작업물·클럽·채팅 이력이 없습니다. | 가입·첫 프로필 등록·첫 권한 안내를 거쳐 진입하고, 빈 화면에서 첫 작업·대화·클럽을 만들 수 있는지 확인합니다. | 02 → 아래 공통 실행 순서 → 25~26의 정리 |

## 준비와 실행 방법

**환경과 계정**

- iOS와 Android에 26.46.0 빌드를 준비합니다. 두 OS에서 모두 실행하되, 특정 OS에서만 지원하는 기능은 해당 OS에서 확인합니다.
- 메시지·첨부·알림을 주고받을 때는 가능하면 상대 기기를 다른 OS로 둡니다.
- 기존 회원, 신규 가입용 계정, 리더·관리자, 멤버, 비멤버를 준비합니다. 수락·거절·내보내기 대상은 서로 다른 계정으로 구분합니다.
- 비밀번호 변경·탈퇴에는 각각 전용 계정을 사용합니다. 일반 종료용 프로젝트와 리더 탈퇴용 프로젝트도 따로 준비합니다.

**데이터 사용 순서**

25~26의 정리 전까지는 계정과 협업 데이터를 유지합니다. 삭제 동작은 별도 테스트용 콘텐츠로 확인하고, 뒤에서 사용할 글·노트·일정·자료는 남겨 둡니다. 나가기·내보내기·차단·종료·해체·탈퇴는 25~26에서 수행합니다.

알림은 각 기능을 실행할 때 수신 여부를 확인하고 남겨 둡니다. 23에서는 받은 알림으로 분류·읽음·이동을 확인합니다. 이미 확인한 항목을 위해 같은 행동을 반복하지 않습니다. 24의 수신 설정 테스트에는 설정을 바꾼 뒤 새로 발생시킨 알림을 사용합니다.

23-4의 ‘나간 클럽 알림’은 25에서 나가기를 수행한 직후 확인합니다.

**확인 범위**

정본의 전체 주요 메뉴에서 정상적인 사용 흐름과 기존·변경 기능, 권한에 따른 차이를 확인합니다. 서버 모듈·Muse 계정·iOS 전용 기능은 준비 조건에 맞게 수행합니다. 미니게임은 실행 대상에 포함하고 갤러리는 제외합니다. 공개 범위 밖의 정보 노출과 나간 회원의 접근 제한도 포함합니다.

네트워크 단절·지연, 파일 용량·글자 수 경계값, 빠른 연속 누르기, 동시 처리, 화면 회전·폴드·글꼴 배율, 모든 OS 버전 조합, 장기 보관·삭제 배치는 이번 실행 범위에서 제외합니다. 오류 재현이나 수정 확인이 필요하면 해당 기능의 상세 QA를 추가로 수행합니다.


## 공통 기능 실행 순서

번호는 기존 결과 기록과의 연결을 위해 유지했습니다. 문서에 배치된 순서대로 진행합니다. 01은 기존 사용자, 02는 신규 사용자가 먼저 수행합니다.

| 순서 | 확인할 기능 | 시나리오 |
|---|---|---|
| 1 | 프로필·기본 정보·커리어 | 03 → 39 |
| 2 | 콘텐츠·소개·커리어·피드·위클리 베스트 | 04 → 37 → 31 → 05 → 36 |
| 3 | 검색 시작·크리에이터·해시태그·전체 결과·필터·Shuffle! | 27 → 28 → 29 → 06 → 07 → 30 |
| 4 | 인맥·다이얼·노크·오픈채팅·Club | 32 → 08 → 33 |
| 5 | 프로젝트·게시판·일정·자료실·채팅 협업 | 09 → 10 → 11 → 12 → 13 → 14 → 15 → 16 → 17 → 18 |
| 6 | 팀 생성·합류·연락·작업 | 19 → 20 → 21 → 22 |
| 7 | 알림·내 활동·계정 보안·앱 밖 진입 | 23 → 24 → 34 → 35 → 38 |
| 8 | 권한 상실·종료·해체·탈퇴 | 25 → 26 |

32의 팀 팔로잉 메뉴는 19에서 팀을 만든 뒤, 35의 차단 해제는 25에서 차단한 직후 확인합니다. 그 외 준비 데이터가 없는 단계는 선행 시나리오에서 생성한 후 이어서 수행합니다.

검색 기능과 주요 메뉴별 대조 근거는 [정본 대조표](audit.md)에서 확인합니다.

**사용자:** 기존 회원  
**준비:** 이전 버전에 글·프로젝트·팀·채팅 기록이 있는 계정을 사용합니다.

| 단계 | 하는 일 | 확인할 결과 |
|---|---|---|
| 01-1 | 업데이트 전 프로필·내 콘텐츠·참여 클럽·알림 설정을 기록한 뒤 26.46.0으로 업데이트하고 실행합니다. | 기존 계정으로 진입하며 기록한 정보와 설정이 유지됩니다. 새로 추가된 설정은 이번 버전의 초기값을 따릅니다. |
| 01-2 | 기존 프로젝트·팀·채팅방을 각각 엽니다. | 개편된 화면에서 기존 기록을 확인할 수 있습니다. 기존 공지는 유형별 변경 기준과 대조합니다. |
| 01-3 | 로그아웃한 뒤 다시 로그인합니다. | 같은 계정으로 로그인되며 다른 계정의 정보가 섞이지 않습니다. |
| 01-4 | 앱을 종료한 뒤 다시 엽니다. | 로그인이 유지되고 주요 화면을 사용할 수 있습니다. |

| 26-4 | 일반 회원과 별도 프로젝트의 리더 계정을 각각 탈퇴시킵니다. | 기존 인증정보로 로그인되지 않습니다. 리더가 탈퇴한 프로젝트는 종료되며 남은 멤버에게 리더가 ‘알 수 없는 사용자’로 보입니다. |

## 결과 기록과 완료 기준

01은 기존 사용자, 02는 신규 사용자에게만 적용합니다. 나머지 시나리오는 사용자 유형과 실제 역할에 맞춰 수행합니다. 신규·기존 사용자의 같은 단계를 모두 수행하라는 의미는 아닙니다.

[실행 기록표](record.md)에 iOS·Android 결과를 각각 남깁니다.

| 결과 | 기록 기준 |
|---|---|
| 미실행 | 아직 실행하지 않았습니다. |
| 통과 | 해당 시나리오에서 확인할 결과를 모두 충족했습니다. |
| 실패 | 기대 결과와 다른 동작을 확인했습니다. 단계 번호·실제 결과·화면 또는 영상을 남깁니다. |
| 막힘 | 앞 단계 오류나 준비 조건 미충족으로 실행할 수 없습니다. 원인을 남깁니다. |
| 기준 확인 필요 | 기대 동작이 없거나 자료마다 달라 합격 여부를 판단할 수 없습니다. 실제 동작과 확인할 기준을 남깁니다. |

한 시나리오 안에서 결과가 갈리면 해당 단계 번호를 함께 적습니다. 일부 단계만 확인한 상태를 시나리오 전체 통과로 기록하지 않습니다.

기준이 불분명한 단계는 실제 동작을 기록하고, 나머지 확정된 단계는 계속 실행합니다. 검색 순서·필터 유지·기존 공지 처리·재참여 제한·해체처럼 정책 대조가 필요한 항목은 기준을 확인한 뒤 판정합니다.

두 OS의 모든 대상 단계에 결과를 남기고, 실패·막힘·기준 확인 필요 항목을 구분하면 이번 실행을 마칩니다. 39개 시나리오의 실행 완료와 출시 가능 여부의 판단은 구분합니다.
